AI Agent 入門｜把 AI 變成能接力的工作助理

簡易摘要講稿，共 20 章；每章包含總覽與逐段圖解，頁底顯示連續頁碼與總頁數。畫面採報告簡報版式，每頁先講三個重點；點圖可補充分工與細節，←／→ 可逐步講解，最後一段接續下一章；↑／↓ 切換章節，P 播放／暫停。互動練習與完整範本收在右上角選單。以整理研究資料為例，所有研究數字與畫面均為教學示意。

1. 把一件事交給 AI，然後呢？

先從大家熟悉的「幫我整理資料」出發，不急著背縮寫。問聽眾：你最後想拿到一句回答，還是一份可以用、可以繼續的成果？

  • 帶走重點：Agent 的價值：把理解、操作、檢查與保存串成一段工作。

2. AI 助理，像一張有人工作的桌子

依序點模型、工具、Agent、框架、介面。用「有腦、有手、有工作桌，才做得成事」幫助理解，但提醒這是比喻。

  • 帶走重點：先問「它看得到什麼、能操作什麼」，再看它叫什麼名字。

3. 它怎麼把工作做完？

播放一次流程，在「看結果」停下，指出示意數字差十倍。說明為什麼需要查原文。

  • 帶走重點：可靠的循環：做一步 → 看結果 → 修正 → 驗證 → 保存。

4. 交代清楚，比只說「幫我研究」更有用

切換三個選項，再複製示範指令。讓聽眾看到「先講清楚」如何減少誤解。

  • 帶走重點：一個好任務＝成果＋資料範圍＋限制＋檢查方式。

5. 聊天視窗和黑底視窗，差在哪？

先顯示圖形介面，再切命令列，最後一起使用；用同一項任務說明差別。

  • 帶走重點：CLI 不會自動讓模型變聰明；模型、工具、資料與權限才影響能力。

6. 先選工作方式，再選產品

不用宣稱哪個最好。請聽眾先選需求，說明最少需要哪些能力。

  • 帶走重點：產品可以換，檔案、規則與驗證方法要能帶走。

7. AI 當下看見的，只是桌面上的資料

用桌面和書櫃區分「有資料」與「正在參考資料」。點每件物品，請大家用自己的話再說一次。

  • 帶走重點：保存在哪裡、怎麼找回、這次有沒有讀到，是三個不同問題。

8. 換個對話，為什麼好像失憶？

讓聽眾挑一個自己遇過的情況。逐一看原因與對策，避免把所有問題都歸咎於「AI 記性差」。

  • 帶走重點：解法是可更新、可找回、可驗證的專案知識。

9. 留下重點，不用把聊天全部塞進一本書

完成五張卡片的分類。答錯時讀提示，強調一份紀錄也可能需要拆成多份，而不是整段複製。

  • 帶走重點：記憶的品質通常比長度更有用；規則放 AGENTS.md，不堆研究歷史。

10. 明天換一位 AI，也能接著做

播放交接流程。提醒同名產品也未必共享同一份記憶；可攜式檔案才是明確交接物。

  • 帶走重點：新對話的第一句：先讀最新進度，再繼續尚未完成的工作。

11. RAG：先去書櫃找，再回桌面回答

先播放流程，再切關鍵字、語意、混合搜尋。解釋找到與找對是兩件事。

  • 帶走重點：RAG＝找資料 → 挑資料 → 帶進 Context → 回答並查證。

12. 需要一開始就裝向量資料庫嗎？

依序切資料量，最後選精確數值。說明資料量不是唯一判斷標準。

  • 帶走重點：先把筆記與來源做好，確定真的找不到，再增加搜尋系統。

13. 報告寫得很順，不代表研究做對了

請聽眾先選一個證據狀態，再看解釋。區分作者說了什麼、AI 推論了什麼、什麼還沒查清楚。

  • 帶走重點：每個關鍵主張，應能回到來源、頁碼、表格或章節。

14. 建一個不綁平台的研究資料夾

不要一口氣唸所有路徑。點三個最重要的：規則、進度、論文筆記；再介紹比較表與最後報告。

  • 帶走重點：規則、進度、證據與成果分開，換工具時就容易帶走。

15. 每讀完一篇，讓整個專案前進一點

播放整段流程，尤其停在「查核」和「交接存檔」。它們最容易被省略，卻是下次接手的關鍵。

  • 帶走重點：每篇更新筆記與矩陣；每次任務更新進度；決策與教訓按需要更新。

16. Git 像存檔歷史，GitHub 像遠端協作櫃

點版本節點觀察示範差異。強調 commit 不等於上傳，下載檔案也不等於 AI 已經讀過。

  • 帶走重點：Git 管版本；文件存知識；讀取與檢索才把知識帶回工作中。

17. 給它工具，也要說清楚邊界

點「檢查指令」看紅色來路；強調不是不讓 AI 工作，而是讓資料和授權各守其位。

  • 帶走重點：資料可以被引用，但不能自行升級成操作權限。

18. 花費看用量，不是看開了幾個對話

切換兩種讀法，再講訂閱和 API。避免用固定價格或百分比讓聽眾誤以為能保證省多少。

  • 帶走重點：開新對話不會自動越來越貴；每次用了什麼、讀了多少才是重點。

19. 聽起來很像，其實不一樣

挑幾張最容易混淆的觀念卡，例如「RAG 永遠記得」與「Git 就是記憶」。

  • 帶走重點：不靠產品名稱判斷能力；用資料、工具、驗證與保存來判斷。

20. 第一次使用，從一個小任務開始

請聽眾說出自己今天可以做的一個小任務。收尾強調最穩定的核心是文件結構、工作規範、來源驗證和持續進度。

  • 帶走重點：當下看 Context，長期留文件，按需用 RAG，版本交給 Git，流程交給 Agent 並查核。
