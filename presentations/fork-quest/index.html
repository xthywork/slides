THE TWO PATHS
兩條路，怎麼選？
路線 A｜留在 Worktree
在 Codex 的聊天頂部選 Create branch here，在 Worktree 測試、Commit、Push、開 PR。適合平行開發，Local 繼續待在 main。
路線 B｜Handoff 回 Local
在 Codex 聊天頂部選 Hand off → Local，讓 App 搬移聊天和修改，再從平常的 IDE 工作。不要在兩個 Worktree 同時 checkout 同一分支。

          
REMOTE BASICS
origin 與 upstream
自己的專案origin → 自己的 GitHub Repo
Fork 別人的專案origin → 你的 Forkupstream → 原作者 Repo
Worktree 不會產生另一組遠端設定；同一個本機 Git Repository 的 Worktrees 共享 remotes。若 Fork 尚未設定 upstream，先新增原作者的遠端網址；檢查 git remote -v，不要把 PR 推錯倉庫。

        

        
TROUBLESHOOTING
遇到這些狀況，要怎麼辦？

          
GitHub 沒出現 Codex 的修改？
只建立 Worktree 或 Commit，GitHub 都不會自動更新。先看 git status 與 git branch --show-current，確定有分支且 Commit 完成，再執行 git push -u origin feature/login；到 GitHub 選對分支開 PR。

          
出現 already used by worktree，分支無法切換？
Git 不允許同一條本地分支同時被兩個 Worktree checkout。優先從 Codex 使用 Hand off → Local；或讓另一份工作目錄切到別條分支（操作前先確認有無未提交檔案）。先用 git worktree list 確認分支在哪個目錄。

          
看到 detached HEAD，該怎麼辦？
Codex-managed Worktree 預設可能不在任何具名分支上。要從此 Worktree Push，先按 Create branch here（或在正確的 Worktree 目錄使用 git switch -c feature/login），再 Commit / Push。不要把 detached HEAD 當成 GitHub 遠端分支。

          
GitHub 上的 main 更新了，但 Codex 版本還是舊的？
Worktree 不會自動跟 GitHub main 同步。先 git fetch origin 查看遠端變更；通常在原本的 Local main 且工作目錄乾淨時，執行 git pull --ff-only origin main。既有功能分支如需新 main，應先提交並評估 merge / rebase 和衝突，不要直接覆寫。

          
Codex Worktree 缺少 .env、套件或本機設定？
另一個 Worktree 有獨立檔案與安裝目錄；被 .gitignore 忽略的檔案通常不會自動帶入。Codex-managed Worktree 可依官方文件用 .worktreeinclude 指定要複製的 ignored 檔案，必要時在每份 Worktree 執行安裝。密鑰不能提交或 Push 到 GitHub。

          
GitHub Fork 跟 Codex Worktree 同時存在，PR 應該對誰開？
先確認 origin 指向你自己的 GitHub Fork，upstream 指向原作者。完成工作後 Push 到 origin/feature/login；如果是要貢獻原專案，PR 的 base 選 upstream/main（依原專案預設分支調整），head 選你的 Fork 功能分支。Worktree 本身不是另一個 GitHub Fork。
