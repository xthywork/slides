什麼是「服務」？

在背景持續執行的程式，例如提供網站的程式或背景工作。Linux 通常用 systemd 這個服務管理工具來啟停與查詢它們。

管理主機可以也是服務主機

Service Harbor 可以管理同一台電腦上的服務，也能在完成連線設定後管理其他 Linux 電腦。

原理與功能：讀取與持續傳送紀錄

讀取工作紀錄，把新訊息送回畫面。

管理主機透過 journalctl 讀取 Linux 的服務紀錄，再把內容送到瀏覽器。新的紀錄可以接著出現在畫面上。

快速找重點

用關鍵字或訊息嚴重程度篩選，減少在大量文字中翻找的時間。

複製給協助者

複製最近 5、10 或 20 行，把線索交給幫你維護電腦的人。

日誌像服務的工作日記，可提供錯誤線索。畫面保留原始訊息；重新連線時以紀錄位置接續，無法確認完整時會提示缺口。
原理與功能：SSH 遠端連線

先確認對方是誰，再取得服務資訊。

SSH 是一種加密的遠端連線方式。Service Harbor 用專用金鑰連到已加入的主機，執行指定的服務查詢或操作。

加入主機

保存對方的網路位址與登入帳號，建立要連線的主機紀錄。

設定金鑰

將管理網站的公鑰交給對方主機；私鑰留在管理主機，作為連線身分憑證。

核對主機身分

比對主機的「指紋」，確認連到正確電腦，再標記為信任。

查詢與操作

服務加入後，依已設定權限取得狀態、讀取紀錄，或執行允許的啟停動作。

畫面相同，查詢路徑不同

本機直接使用系統工具；遠端透過 SSH 執行固定指令。結果都整理成相同的服務詳情畫面。

信任不等於所有操作都能做

遠端帳號仍需具有對應權限。Service Harbor 沒有提供讓瀏覽器任意輸入指令的操作入口。

原理與功能：從管理主機發出連線

分開確認：服務在跑，入口也通嗎？

服務狀態是向系統詢問「程式是否執行」；連線檢查則是由管理主機實際嘗試「能否連到指定入口」。

原理與功能：服務目錄與本機設定

先記住「去哪裡查」，再整理查到的結果。

加入服務時，保存的是它的位置與管理方式。實際運作狀態則在查詢時取得，不是單靠清單上的文字判斷。

選擇本機、遠端主機或外部網站，指定服務名稱或網址。一般服務註冊會先確認對應的系統服務存在。

保存顯示設定

加入容易辨認的名稱、分類、說明與最愛。設定存放在管理主機的 JSON 文字檔，不需要資料庫。

⇄

匯出與匯入設定

把清單存成檔案；匯入時先檢查與預覽，遇到重複項目可選擇覆蓋或跳過。

匯出不包含登入密碼、私鑰與主機信任資料；新匯入的主機需重新確認信任。新增或移除清單紀錄，不會安裝或解除安裝原本的服務。

原理與功能：單次查詢、定時查詢與串流

不是所有資訊，都用同一種更新方式。

單次

需要時查一下

初次登入、手動刷新或切換篩選等操作，會觸發資料更新。不固定反覆查詢整份服務清單。

3 秒

Live 持續看選取項目

啟用 Live 後，每 3 秒重新查詢目前選取的服務或 Port；換選取項目或離開時停止。

5 秒

鈴鐺啟用限時追蹤

每 5 秒查詢指定項目，可設定追蹤 5、10、20 分鐘或 1 小時，並在總覽顯示倒數。

日誌使用另一條連線

新紀錄透過 SSE 串流傳送。頂端關閉 Live，日誌仍可能繼續追蹤；要用日誌區自己的暫停按鈕。

前端開著，才會繼續查詢

限時追蹤由瀏覽器啟動；關閉網頁便停止查詢，重開後依原到期時間恢復，沒有另外的後端巡檢排程。

運作原理：先驗證，再執行

登入網站，與允許操作服務，是兩道關卡。

能打開畫面，不代表可以執行任何系統指令。每個請求都有對應的驗證與操作範圍。

◎

確認登入狀態

登入後以 session 記住身分，資料查詢需要有效登入。修改設定或操作服務時，也會檢查請求來源。

✓

確認目標與動作

只接受已加入清單的服務與允許的啟動、停止、重啟等動作，使用固定的系統指令。

◇

依系統權限執行

網站以一般帳號執行。自己的使用者服務可直接管理；系統服務需另外授權明確的動作與服務名稱。

瀏覽器與管理網站的預設連線是 HTTP，沒有傳輸加密；遠端主機的 SSH 加密不會保護這一段。因此預設只供可信任私人網路，跨網路另需 VPN 或受控的 HTTPS 入口。
把架構換成容易理解的分工

畫面、處理中心、資料與系統工具。

每一層負責不同工作：前端不直接控制電腦，而是把要求交給後端處理。

▦

前端：讓人看與操作

用 HTML 排內容、CSS 做版面、JavaScript 處理按鈕與更新。直接由瀏覽器執行，沒有額外的前端編譯流程。

⇄

後端：接收與處理要求

由 Python 的 FastAPI 接收查詢與操作。負責登入驗證、找到服務位置、呼叫系統工具，再回傳結果。

⌂

底層：保存與實際執行

JSON 檔保存設定；systemctl 查詢或控制服務；journalctl 讀紀錄；SSH 把指定查詢或指令送到遠端主機。

兩種網路行為分開看

管理遠端系統服務使用 SSH；檢查網站或 Port，則由管理主機直接嘗試 HTTP／TCP 連線，不透過遠端掃描。

實際使用流程

從加入服務，到找到需要處理的地方。

以「某個網站突然打不開」為例，功能可以這樣串接；每一個結果都幫你決定下一步看什麼。

先建立服務目錄

加入主機與既有服務，設定名稱、分類、網站網址與需要的連線檢查。

從總覽找到異常

查看需要關注的項目，搜尋該服務並開啟詳情。

比較兩種訊號

看系統服務是否執行，再看網站或 Port 是否連通，縮小問題範圍。

查紀錄並決定處理

找日誌線索；判斷需要時，在具備權限的情況下啟動或重啟，再觀察結果。

方便回到同一個服務

分類、最愛與搜尋整理入口，網站捷徑可另開新分頁，設定檔匯出／匯入能搬移清單。

看見資訊，再由人判斷

Service Harbor 集中狀態與操作，不會自動修復問題。CPU、記憶體等硬體監控屬於另外的專案。

回到整個運作方式

向主機取資訊，在網頁上集中管理。

查詢

讀取本機或遠端的服務狀態，另外測試指定網站與網路入口是否可連通。

呈現

整理成服務清單與總覽，用選取輪詢更新狀態，用串流接收新日誌。

操作與保存

經過確認與授權後傳送啟停指令；用本機設定檔保存主機、服務與顯示方式。
