User scope

使用該帳號的 user manager，控制不需要 sudo。

System scope

Connectivity

連得上，與服務正常，是兩種訊號。

TCP 檢查從 Dashboard 主機出發，僅探測已記錄的目標，不用 ss 掃描主機。

點選情境，理解檢查結果
●
Open

Dashboard 能連到指定的位址與 Port。

此結果不能證明 HTTP 健康，也不能證明回應的是原本設定的 systemd unit。

手動 Port

可新增、修改與刪除，顯示所屬主機、檢查時間與連通結果。

服務來源 Port

在 Open ports 中唯讀；透過 View service 前往 Services 修改或取消。

網站檢查

可選 HTTP／TCP；HTTP GET 只讀標頭，2xx／3xx／401／403 視為可用，不跟隨轉址、不帶認證，HTTPS 驗證憑證。

有 unit 時，網站檢查只附加連通結果，不覆寫 systemd 狀態。無 unit 且未啟用檢查時維持 Linked／Unmanaged，也不提供控制與 journal。
Hosts

讓遠端服務，接入同一套流程。

專用金鑰、明確的信任步驟，以及固定的非互動指令。

註冊主機

在 Hosts 保存 SSH 位址與使用者，取得 Dashboard 專用 Ed25519 公鑰。

核對身分

掃描取得待核對指紋，使用者獨立比對並確認，才寫入該主機的 known_hosts。

檢查權限

確認 SSH、systemd 與 journal 的可用性；遠端控制需要主機端明確授權。

加入服務

Add service 指向已信任主機，唯讀確認 unit 存在後，納入狀態與日誌管理。

金鑰留在本機

私鑰僅保存在 data/ssh；公鑰 API 不回傳私鑰，SSH 嚴格比對已核對的 host key。

執行範圍明確

透過固定的狀態、journal 與控制指令分派；沒有任意 shell API，也不登入遠端掃描 Port。

保存設定新主機維持未信任；匯入不執行 SSH 或 systemctl
設定交換不帶入 SSH 私鑰、密碼與指紋。從 Dashboard 移除註冊，只刪除紀錄，不刪除系統 unit。

Trust & permissions

網站以一般帳號執行。

把登入、命令與主機信任分開管理，系統控制範圍由明確授權決定。

⌁

登入與請求

密碼驗證、登入限速、持久化且雜湊儲存的 session。資料 API 需登入；寫入 API 額外驗證 Origin。

✓

命令與單元

使用固定 argument list 與 subprocess。System 控制先檢查 allowlist，再以 sudo -n 執行精確動作與 unit。

◇

資料與主機

SSH 使用專用金鑰及嚴格指紋核對；密碼、session、主機資料、私鑰、服務清單與 journal 不納入 Git。

預設 HTTP 沒有傳輸加密，登入密碼、cookie 與日誌可能遭沿途讀取或竄改。僅供可信任私人網路；勿直接開公網 Port forwarding。跨網路應另設受控 VPN，或 HTTPS 反向代理與存取限制，安裝器不提供 TLS。

以上為專案文件描述的機制，本簡報未執行完整程式碼安全審查或滲透測試。

Deployment reference

兩種安裝入口，相同的部署流程。

Ubuntu 上以一般使用者執行安裝器，設定密碼、監聽位址、Port 與 systemd 模式。

文件中的命令 · 僅供閱讀
# 標準 Python venv / pip
bash scripts/setup.sh

# 或先自行準備 uv
bash scripts/setup-uv.sh

# 預設監聽位址
0.0.0.0:8765

# 開啟 Dashboard
http://<主機區網 IP>:8765/
venv／pip

需 Python 3、pip、venv；缺少時提示 apt 指令，不自動安裝 apt 套件。

uv

使用 uv venv 與 uv pip，仍需 Python 3，不要求 python3-pip／python3-venv。

User／System

兩種模式都由一般帳號執行網站；User 模式設定 linger，支援未登入時開機啟動。

必要權限

僅必要系統設定要求 sudo；安裝器不建立免密碼 sudoers。

本次只製作與提供簡報，未 clone、下載或安裝 Service Harbor，也未執行本頁的安裝命令。
Operations & lifecycle

設定能重建，私密資料要另行備份。

Reset

重設部署設定

bash scripts/reset.sh

重設密碼、監聽位址與 Port，重建 systemd；保留服務、Hosts 與 SSH key。撤銷舊 session，沿用上次成功的安裝工具。

Uninstall

移除 Dashboard

bash scripts/uninstall.sh

停用並移除 Dashboard systemd、密碼、資料、SSH key 與 .venv，保留原始碼；需輸入 REMOVE 確認。

不連帶刪除受管服務

重置與移除會顯示步驟並要求確認，不刪除其他被管理的服務；既有 sudoers 與 linger 不自動移除。

Git 不是資料備份

data/、dashboard.env、私密 local-catalog、金鑰與主機設定需另做私密備份。服務 JSON 匯出不能取代完整部署備份。
